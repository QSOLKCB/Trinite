# Geometry instrument and artifact contract

Phase 4 implements detached prompt capture and native-space analysis. Training remains unchanged, with geometry loss zero. The protocol and controls are in [GEOMETRY-PROTOCOL.md](GEOMETRY-PROTOCOL.md); [PHASE-4.md](PHASE-4.md) records observed results and limits.

## Frozen reference

The analysis kernel is an exact, unmodified copy of QSOL-GEO-REASON's geometry.py at e770f585bf3136b47a657772156116d5f02b1e77, retained as src/trinite/_geo_reference.py. [geometry-pin.json](../src/trinite/geometry-pin.json) binds the upstream path, Git blob SHA-1 and raw SHA-256 for that kernel, its Apache-2.0 license, mathematical/scientific contracts and original 19 numerical tests. The runtime checks its two shipped upstream files; repository tests check all five. The upstream code is an engineering dependency, not training data. The license and pin ship with the wheel; original bytes/notices are preserved.

geometry.py validates bounded detached coordinate lists and calls the actual pinned functions for forward differences, path length, cosine, arclength alignment and Menger curvature. It does not introduce a second geometry kernel. Synthetic analytic fixtures and the unchanged upstream tests independently check known results and degeneracies. Test-only import names map to the frozen kernel while loading the original suite; the production package does not install or substitute QSOL-GEO-REASON's broader capture stack.

Metrics preserve GEO-MATH-001–010 definitions. Zero vectors follow C(0,0)=1 and C(0,v)=0; empty finite-difference means are rejected, and unavailable curvature summaries use null with an explicit status. Arclength comparisons resample both sides to max(sample counts), preserving endpoints and exact-zero handling. Menger uses upstream's exact dyadic-rational determinant followed by binary64 conversion, without an epsilon that erases nonzero curvature. The adapter supplies an explicit Decimal context so caller rounding/traps cannot redefine that calculation, and restores the caller context.

This integration uses the numerical kernel API, not the simulation runner's decimal-normalized result serializer. Exact represented float32 coordinates are promoted losslessly to binary64; artifacts store canonical float.hex strings without decimal rounding. Every metric is computed from those same retained coordinates. JSON is Trinite's versioned payload format; upstream PROVENANCE record serialization remains delegated to its own pinned implementation.

## Capture and request binding

capture.py records prompt-only hidden states at final and block.0 from one CPU float32 causal forward. Each trajectory point corresponds to one selected UTF-8 byte-token position; BOS/EOS/PAD states are excluded. The full tokenizer IDs, attention/loss masks and byte spans remain in the record, including special-token null spans. Context is cumulative causal prefix, pooling none and transform identity. No hooks, answer tokens, gradients or optimizer steps are introduced.

Each trinite.prompt-capture.v1 record contains model configuration/lane/inventory identity, source prompt/hash, extraction settings, logits identity and named trajectory shapes/raw float32 identities/hex coordinates. audit_capture rejects unknown fields, changed token IDs/spans/positions/settings, mismatched shapes/dtypes/identities, nonfinite values and hex values that cannot represent the exact float32 bytes. This audit proves artifact structure and byte consistency; hash checks alone do not independently prove model origin or scientific validity.

geometry_run.py composes validated elected Phase 3 checkpoints with that instrument. freeze-observation creates a new request directory and binds the exact plan/data/checkpoint/source/environment/pin identities before geometry is extracted. The protocol was publicly committed at [7ebe475](https://github.com/QSOLKCB/Trinite/commit/7ebe475f1e62f4675e2525dbed7ddba441db1998) before the first target geometry outcomes. The caller supplies the request's exact identity to measure-observation; modified request/input/source/environment bytes reject preflight. A local timestamp is explicitly not independent registration assurance.

Checkpoint loading temporarily restores retained RNG states, so orchestration saves/restores caller Python/NumPy/Torch RNGs. Before/after checkpoint bytes must agree for every captured model, including parameters, optimizer moments, progress and RNG. Request creation/capture and numerical control generation make no model RNG draws. Rademacher signs derive from seed/item/layer/point/coordinate hashes; no stateful RNG or label fitting is used.

## Result and verification scope

New observation directories retain the frozen request, two model inventories, two trinite.capture-set.v1 JSON files, two complete lane geometry results, combined result/report and PROVENANCE bundle/report. Every lane includes all 36 training prompts, every native trajectory's differences/length/curvature, all nine pairs per family and all six family contrasts at both layers for native, reversed-order and random-vector conditions. No negative/null result or diagnostic is suppressed.

The primary contrast is the equal-family mean of same-item/different-carrier cosine minus same-carrier/different-item cosine. Operands vary within a fixed modular-add operation; this is not an independent variation of logical operation type. The visible training split is explicitly exposed. No test-family geometry, inferential interval, p-value, geometry intervention, projection, causal mechanism or fresh capability claim follows.

The frozen protocol calls reversal an order-sensitivity control. Reversing both paths actually tests orientation invariance of paired arclength/order-1 cosine; it is not an independent order-scrambling null. This limitation is retained in result records rather than silently changing the frozen control after inspection. Random-vector and carrier/item controls serve different purposes. A future independently shuffled-order analysis requires a new frozen protocol before its target outcomes are inspected.

Preflight failures reject before creating an observation directory. Once computation starts, failures retain an explicit result/report and any completed lane files. Mandatory observer errors preserve computational files but return nonzero and false evidence eligibility. Stable filesystem reads are assumed; this is not a hostile concurrent-writer snapshot guarantee. The unchanged upstream verifier checks closed retained artifacts, canonical records, membership and references; it does not certify that a geometric interpretation is true. release_ready remains false.

Limits: exact tiny seed-0 plan, final step 60, six training families, context 32/width 16, 72 prompt captures with two layers, 4 MiB total capture JSON, 512 KiB checkpoint tensor input per lane, and 120 seconds checked between items/pairs/stages. Low-level geometry lists permit up to 256 points by 128 dimensions and reject out-of-domain/nonfinite outputs. These are algorithm/artifact bounds, not a whole-process memory cap or OS timeout. Reports retain wall/observer time and Linux process-lifetime peak RSS; hosted smoke is not an edge benchmark.

Replay remains scoped to the same source/environment fingerprint. CLI changes alter the existing training source receipt: produce checkpoints with the current tree for this observation, or use the original implementation to replay older checkpoints. No previously frozen receipt is weakened or rewritten for compatibility.
