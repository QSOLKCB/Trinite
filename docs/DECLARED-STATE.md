## Useful adaptation

The checkout-only `scripts/declared_state/` package provides a strict, dependency-light codec and a
read-only text observer. The five labels retain the legacy order and vocabulary:

| Label | -1 | 0 | +1 |
| --- | --- | --- | --- |
| K, declared knowledge sufficiency | unknown | partial | sufficient |
| C, declared constraint clarity | conflicting | unclear | clear |
| R, declared hallucination risk | low | medium | high |
| A, declared action | ask | answer | refuse |
| S, declared length target | minimal | normal | expanded |

These are **producer-declared labels**, not readings of internal beliefs,
calibrated probabilities or verified truth. A dishonest or mistaken answer can
have a syntactically perfect label. The observer does not infer any label from
keywords, punctuation, word counts, latent activations or hidden states.

### Codec contract: `trinite.declared-five-trit.v1`

`encode_state(state)` accepts exactly a built-in tuple of five built-in integers
in `{-1,0,+1}`. Booleans, floats, subclasses and arbitrary iterables fail with
`ContractError`. Each signed trit maps to `trit + 1`; K is most significant:
`value = 81*(K+1) + 27*(C+1) + 9*(R+1) + 3*(A+1) + (S+1)`.

`decode_state(code)` accepts only canonical four-character `0xHH` strings with
uppercase hexadecimal digits, from `0x00` through `0xF2`. All 13 reserved byte
values `0xF3`–`0xFF`, lowercase hex digits, alternate prefixes, whitespace,
signs and extra characters fail. It returns the same immutable ordered tuple.

Examples: all-minus = `0x00`, all-zero = `0x79`, all-plus = `0xF2`, and
`(-1,+1,+1,-1,-1)` = `0x48`. `0x1A` decodes to `(-1,-1,+1,+1,+1)` and declares
REFUSE, not ASK.

The 243 states fit numerically in one byte; the textual `0xHH` encoding occupies
four ASCII bytes, before separator/body and tokenizer framing. This codec is
**not** a replacement for [packed ternary weight codes](INFERENCE.md#implemented-code-payload-preparation),
which have different code ordering, padding, metadata and numerical semantics.

### Observer contract: `trinite.declared-output-observation.v1`

`observe_output(raw_output, exact_words=None, banned_chars=())` returns a frozen
`OutputObservation` with the exact original string, optional code/state/body,
optional word count, stable issue names and schema. It accepts at most 65,536
Python string characters; this is not a byte or token bound. No file, subprocess,
model, network, random generator or training call occurs.

- The envelope is canonical `0xHH`, one ASCII space, then the body. Subsequent
  spaces/newlines are body characters and are retained. Leading whitespace,
  missing separators and adjacent suffix digits fail rather than being repaired.
- A bad code gives `invalid_state_code`; a missing separator gives
  `missing_separator`. These malformed envelopes have no interpreted body/state.
  All raw text remains available to the caller.
- Empty/Unicode-whitespace-only bodies give `empty_body`.
- Explicit `exact_words` is a built-in integer in `[0,65536]`; Python `str.split()`
  defines words using Unicode whitespace. Both too few and too many words give
  `exact_word_count_mismatch`. A zero target never makes an empty answer valid.
- `banned_chars` is an exact tuple of at most 256 unique one-character built-in
  strings. Matching is case-sensitive, without Unicode normalization. A match
  gives `banned_character_present`. Include both `e` and `E` to forbid both.
- Invalid caller arguments raise `ContractError` even if model text is malformed.
  Issues are reported in the fixed order above; no aggregate or correctness score
  is produced. An empty issue list means only these explicit checks passed.

The caller must preserve original generated bytes separately if decoding to
Python text loses information. This observer does not certify UTF-8 validity,
source identity, custody, model origin, truth, task correctness, actual action,
refusal calibration or semantic equivalence. It does not add punctuation,
truncate, replace, normalize or otherwise repair model answers. It does not
supplant the existing authoritative exact-answer/EOS scorer.

Run from the checkout with `PYTHONPATH=src:scripts`:

```python
from declared_state import encode_state, decode_state, observe_output

assert encode_state((-1, 1, 1, -1, -1)) == "0x48"
assert decode_state("0x48") == (-1, 1, 1, -1, -1)
observation = observe_output("0x48 a b", exact_words=2)
assert observation.raw_output == "0x48 a b"
assert observation.issues == ()  # Syntax/count only, no semantic claim.
```

### Concrete legacy reproduction findings

Source review and bounded reproductions found the issues below. Executed checks
imported only reviewed dependency-free state, dataset, evaluation and wrapper
definitions. Subprocess/grammar behavior and logic semantics were source review,
not external-runtime conformance. No model subprocess, training, download or GPU
code was executed. Original input bytes are unchanged.

1. The README's `(-1,1,1,-1,-1)` example actually encodes as `0x48`, not its stated
   `0x08`; its separate `0x1A` ASK illustration declares REFUSE. The encoder accepts
   `True` and `1.0` as integer keys; the decoder accepts aliases such as repeated
   prefixes and lacks a lower-bound check.
2. `generate_variations(per_category=0)` and `per_category=100` both append the
   same three rows. The gravity response contains `e` despite banning it.
   Earlier manual-count allegations about the seed examples were withdrawn:
   photosynthesis correctly has eight words and evolution correctly has ten.
   Neither is a word-count bug; the scorer defect below is independently verified.
3. At least four seed prompts exactly overlap evaluation prompts: the redacted
   capital, contradictory A, eight-word photosynthesis and thunder questions.
   Reusing them would measure exposure, not fresh generalization.
4. `score_epistemic_honesty({"expected_action":"ANSWER"}, "")` and
   `score_minimality({}, "")` each return **2/2** for an empty answer.
   `score_constraint_compliance({}, "0xFF body")` gives **2/2** to a reserved state;
   the `max_words=8` test also gives **2/2** to a one-word response. Exact count is
   not a maximum. The entropy banned-letter gold itself contains `e`.
5. Substring heuristics are not truth checking: a refusal marker embedded in a
   false assertion can score well, while benign text can trigger ask markers.
   Shared boilerplate can maximize word-overlap “stability” without equivalent
   meaning. The separate refusal percentage has only one impossible-query case
   and is not included as a fifth independent component of the DS-5 aggregate.
6. `parse_output("  0x48 body")` returns body `"48 body"`: matching uses a stripped
   string while slicing uses the original. Prefix matching also accepts adjacent
   text without a boundary. `enforce_state("0x48", "A false statement")` returns
   `"A false statement?"`; adding `?` does not create a valid clarifying question.
7. Both runners ignore nonzero subprocess exit status; the inference wrapper
   silently omits a missing grammar file. The grammar admits `0xFF` but forbids
   digits such as the `2` used by its own prime-number gold. No runtime conformance
   was performed for the legacy grammar or external training stack.
8. The contradictory-A gold's assertion that no valid conclusion follows is not
   generally correct without specifying the logic (classical explosion versus
   alternative logics). Such examples need explicit formal semantics and a
   checked oracle, not a blanket refusal label.

## Compatibility, checks and deferred research

Affected requirements: TRI-I01/I05/I12 (inspectable standard-library CPU-only
boundary), TRI-I06 (no output/RNG mutation), TRI-I14 (versioned opt-in semantics).
TRI-I02/I03/I07/I11 remain intact: no native initialization, admission, historical
source closure, example/split, scorer, training request or fixture changes.
The checkout-only package imports only standard-library helpers and existing
contracts; no core runtime imports it. Keeping it outside `src/` also preserves
the complete recursive CNR-001 v15 source inventory, not just flat closures.
It is not an installed-wheel API. No PCGrad/LSQ or scale-refit numerical path is touched.

Run `PYTHONPATH=src python -m unittest discover -s tests -p test_declared_state.py -v`.
The tests independently enumerate all 243 states and all 256 byte spellings,
check invalid types/aliases, bounds, raw preservation, empty/malformed responses,
strict count/bans and dependency isolation. Root discovery also runs them in the
existing CPU conformance workflow. These checks are software evidence only.

Future declared-action learning would require a separate proposal: bounded
formal task semantics, independent labels/oracles, file-level rights/admission,
parent-family splits and exposure records; freeze dataset/protocol/source before
outcomes. Keep raw model correctness, declared-label agreement, abstention
coverage, false refusal and any grammar/repair intervention separate. Report
all failures and avoid tuning on exposed evaluation families. Neither a label
codec nor a synthetic refusal response proves internal knowledge or honesty.
Original learning, fresh confirmation, geometry-on Phase 5, format selection,
scaling and release gates remain unchanged.
